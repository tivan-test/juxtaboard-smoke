# Автотесты Juxtaboard

Смоук- и регресс-тесты сайта [Juxtaboard](https://juxtaboard.com) на Playwright + TypeScript.
Один запуск: вход → создание пространства прогона → смоук (SM-XX) → регресс (RG-XX) в том же пространстве →
удаление пространства → отчёт `runs/<дата>/report.md` со скринами упавших тестов.

## Требования

- Docker с плагином `docker compose` (v2). Больше ничего ставить не нужно.
- Учётная запись Juxtaboard (почта и пароль).
- Без Docker: [bun](https://bun.sh) 1.4.4 и браузеры Playwright (`bunx playwright install chromium`).

## Запуск

```bash
git clone https://github.com/tivan-test/juxtaboard-smoke.git && cd juxtaboard-smoke
cp .env.example .env        # и заполните JB_EMAIL, JB_PASSWORD
docker compose run --rm tests
```

Первый запуск сам соберёт образ. После изменений в коде пересоберите: `docker compose build`.

Без Docker то же самое: `bun install`, затем `bun run test:all`.

## Один тест или часть набора

Параметры пишутся после `--`:

```bash
docker compose run --rm tests -- -g "SM-03 "              # один тест (пробел после номера: иначе SM-03 найдёт и SM-030…)
docker compose run --rm tests -- -g "SM-0[1-5] |RG-01"    # шаблон: первые пять смоук-тестов и RG-01
docker compose run --rm tests -- --only smoke             # только смоук
docker compose run --rm tests -- --only regress           # только регресс
bun run test:all -- -g "SM-03 "                           # то же без Docker
```

`-g` — регулярное выражение Playwright по названию теста.

## Где отчёт

`runs/ГГГГ-ММ-ДД_ЧЧММ/` (время московское):

- `report.md` — итог по разделам «Смоук» и «Регресс»: сколько прошло, какие упали, на каком шаге, ожидание и фактический результат;
- `SM-XX.png` / `RG-XX.png` — скрин упавшего теста;
- `run.log` — полный вывод Playwright.

Код выхода: `0` — всё прошло, `1` — есть падения (или не удалось удалить пространство), `130` — прогон прерван.

## Важно: тесты идут на рабочем сайте

Тесты работают на **настоящем** juxtaboard.com под учётной записью из `.env`.

- Каждый прогон создаёт пространство `TEST_ГГГГММДД_ЧЧммсс` и в конце **всегда** его удаляет — и после падений, и после Ctrl+C.
  Если удаление не удалось, это написано в отчёте и в конце вывода: удалите пространство вручную.
- Всё, что создают тесты, называется с префиксом `TEST_`.

## Правила безопасности

1. Тесты меняют и удаляют только то, что начинается с `TEST_`. Чужие пространства не трогаются.
   Удаление есть только в `tests/setup/space.cleanup.ts` (пространство прогона) и в SM-02 (своё пространство `…_SM02`), всегда по точному имени.
2. Никогда не меняются пароль, почта, оплата; не удаляется учётная запись; не приглашаются реальные люди.
3. Тест, который меняет настройку (имя, тема, язык), в конце возвращает её обратно.
4. `.env` (пароль) и `auth/` (сессия входа) не попадают ни в git, ни в Docker-образ. Не пересылайте их.
   После прогона скрипт проверяет, что пароля нет в отчёте и логе.

## Устройство

```
tests/setup/     вход, создание и удаление пространства прогона
tests/smoke/     смоук-тесты SM-XX
tests/regress/   регресс-тесты RG-XX
tests/support/   общие помощники
scripts/run.ts   запуск: смоук → регресс → удаление пространства → отчёт
scripts/report.ts  отчёт из результатов Playwright и названий шагов в тестах
deploy/install.sh  установка на сервер (Linux): проверки, сборка, пробный прогон
```

Проверки кода: `bun run lint`, `bun run typecheck`.

## Частые проблемы

- **«Слишком много попыток» / вход не проходит.** Сайт ограничивает частые входы.
  Сессия сохраняется в `auth/session.json` (папка `auth/` подключена к контейнеру), поэтому повторные прогоны входят без пароля.
  Не удаляйте `auth/` без нужды; если вход заблокирован — подождите и запустите снова.
- **`env file .env not found`** или тесты не могут войти: нет `.env` или в нём пустые `JB_EMAIL` / `JB_PASSWORD`.
  Выполните `cp .env.example .env` и заполните.
- **Тест упал, в отчёте «пространство прогона не создано».** Не прошёл вход или создание пространства — смотрите `run.log`.
- **Файлы в `runs/` и `auth/` принадлежат root (Linux).** Контейнер пишет от root; удалить можно через `sudo` или `docker compose run --rm --entrypoint rm tests -rf runs/<папка>`.
